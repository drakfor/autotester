# Autotester 0.1.0

Autotester — экспериментальный CLI-инструмент для генерации и запуска unit-тестов для C++-функций с помощью Ollama и Google Test.

Инструмент читает исходный файл, отправляет его языковой модели, преобразует полученные тест-кейсы в C++ и запускает тесты после компиляции. Сгенерированные входные данные и ожидаемые результаты требуют проверки: модель может ошибаться, а успешное прохождение тестов не гарантирует корректность программы.

## Как это работает

```text
C++-исходник → Ollama → JSON-тест-кейсы → Google Test → g++ → запуск тестов
```

1. CLI принимает путь к одному исходному файлу.
2. Ollama генерирует ответ по JSON-схеме, которую проверяет Pydantic.
3. Генератор создаёт файл `<имя>_tests.cpp` с проверками `EXPECT_EQ`.
4. `g++` компилирует тесты с C++20 и Google Test.
5. При успешной компиляции Autotester запускает полученный исполняемый файл.

## Требования

Инструкция ниже рассчитана на Linux с Bash. Поддержка других платформ в версии 0.1.0 не заявлена.

- Python 3.12 или новее и `pip`.
- Python-пакеты `ollama` и Pydantic 2.
- Установленный и запущенный сервис Ollama с моделью `test-generator`.
- Компилятор `g++` с поддержкой C++20 и pthread.
- Git и CMake для загрузки и сборки Google Test.

## Установка

Выполните команды из корня репозитория:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
python -m pip install ollama "pydantic>=2,<3"
```

В версии 0.1.0 зависимости `ollama` и `pydantic` ещё не объявлены в `pyproject.toml`, поэтому устанавливаются отдельно. Используйте установку в режиме `-e`: поиск Google Test привязан к расположению исходников проекта.

### Подготовка Google Test

Из корня репозитория загрузите Google Test, если каталог `googletest` ещё отсутствует:

```bash
git clone https://github.com/google/googletest.git googletest
```

Соберите статические библиотеки:

```bash
cmake -S googletest -B googletest/build -DBUILD_SHARED_LIBS=OFF
cmake --build googletest/build
```

Autotester ожидает следующие пути относительно корня репозитория:

```text
googletest/googletest/include/gtest/gtest.h
googletest/build/lib/libgtest.a
googletest/build/lib/libgtest_main.a
```

Пути заданы в `src/autotester/cpp_compiler.py`. Системная установка Google Test не заменяет эту настройку автоматически.

### Подготовка модели Ollama

Если сервис Ollama ещё не запущен, запустите его в отдельном терминале:

```bash
ollama serve
```

Autotester обращается к модели с фиксированным именем `test-generator`. Создать её можно на основе `qwen2.5-coder:14b`, указанной в примере настройки в исходном коде. Для загрузки базовой модели потребуется интернет, а для её запуска — достаточные ресурсы компьютера.

```bash
ollama pull qwen2.5-coder:14b
```

В терминале с активированным Python-окружением выполните:

```bash
python - <<'PY'
import ollama
from autotester.llm_settings import system_prompt

ollama.create(
    model="test-generator",
    from_="qwen2.5-coder:14b",
    system=system_prompt,
)
PY
```

Это разовый шаг подготовки модели. Сам CLI модель не создаёт и не передаёт `system_prompt` при каждом запросе; приведённая команда сохраняет инструкции в создаваемой модели.

## Пример использования

Создайте файл `example.cpp`:

```cpp
int Max(int a, int b) {
    return a > b ? a : b;
}
```

Из каталога, содержащего этот файл, запустите:

```bash
autotester example.cpp
```

Python-окружение с установленным Autotester должно быть активировано. Запускайте команду именно из каталога исходника: сгенерированный файл подключает исходник по имени, без полного пути.

При успешной генерации и компиляции в текущем каталоге появятся:

```text
example.cpp          # исходный код
example_tests.cpp    # сгенерированные тесты
example_tests        # исполняемый файл тестов
```

Результаты Google Test выводятся в терминал. Повторный запуск перезаписывает файл сгенерированных тестов; при успешной компиляции исполняемый файл также обновляется.

Пример возможной проверки — конкретный ответ модели может отличаться:

```cpp
TEST(MaxTests, DifferentPositiveNumbers) {
    EXPECT_EQ(Max(5, 3), 5);
}
```

Для повторного запуска уже скомпилированных тестов:

```bash
./example_tests
```

Справка CLI:

```bash
autotester --help
```

## Возможности и ограничения версии 0.1.0

- Схема тест-кейсов допускает типы `int`, `double`, `float`, `bool`, `char`, `string` и `vector<int>`.
- Обрабатывается один исходный файл. Настройки сборки многофайлового проекта, дополнительные библиотеки и флаги компилятора через CLI не поддерживаются.
- Предполагаются функции, которые можно непосредственно вызвать из теста. Отдельной поддержки методов классов и создания объектов пока нет.
- Для примеров используйте исходник без собственной функции `main()`: точку входа тестового приложения предоставляет Google Test.
- Схема требует хотя бы один аргумент функции. Функции без аргументов и возвращаемый тип `void` не поддерживаются.
- Все проверки используют `EXPECT_EQ`, в том числе для `float` и `double`; сравнение с допустимой погрешностью не реализовано.
- Строки и символы вставляются в C++ без экранирования. Кавычки, обратные слеши и переводы строк могут привести к некорректному коду.
- Проверка JSON-структуры не гарантирует корректность значений, имён тестов или ожидаемых результатов.
- Тайм-аут запуска всего тестового исполняемого файла составляет 5 секунд. При превышении возникает исключение; тайм-аут компиляции не задан.
- Имя модели, пути к Google Test и тайм-аут нельзя изменить аргументами CLI.
- CLI не передаёт код завершения тестового процесса наружу. Ошибка компиляции также не устанавливает ненулевой код выхода CLI. Для CI нельзя полагаться на код выхода команды `autotester` как на признак успешной проверки.


## Структура проекта

```text
pyproject.toml                 # версия пакета и команда autotester
src/autotester/
├── cli.py                     # последовательность генерации, сборки и запуска
├── scanner.py                 # аргументы командной строки
├── llm_settings.py            # запрос к Ollama и инструкции для модели
├── format.py                  # Pydantic-модели тест-кейсов
├── generate_cpp.py            # преобразование тест-кейсов в Google Test
└── cpp_compiler.py            # вызов g++ и запуск исполняемого файла
```

Google Test размещается в локальном каталоге `googletest/`, который исключён из Git. Имеющийся локально каталог `tests/` также исключён из Git; его содержимое не является обязательной частью установки.
